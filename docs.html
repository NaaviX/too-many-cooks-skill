Le concept

Deux pièces, jamais plus

Chaque intégration combine toujours les deux mêmes morceaux. Ce dépôt ne produit que le second.

🔌

1 · Le serveur MCP

Le paquet npm @toomanycooks/mcp-server donne à l'agent les outils (find_arbitrage_strategies, get_historical_funding…). Il vit ailleurs ; ce dépôt ne le contient pas.

externe · lancé via npx
🧠

2 · La skill / rule (ce dépôt)

Donne à l'agent le savoir-faire : quel outil saisir, comment lire un APR, quels caveats remonter. Sans elle l'agent a les outils mais les appelle naïvement ; avec elle, il se comporte comme un analyste quant.

prose + recettes → dist/
Architecture du build

Contraintes dures

tickers en MAJUSCULES, 1–20/appel · count ≤ 50 · periodDays ≤ 30 (60 pour coûts) · size ∈ 1k|5k|10k|50k|100k · clés d'exchange en minuscules.

Slash commands

3 commandes (plugin Claude Code)

Livrées dans le plugin via l'extra slash-commands. Disponibles uniquement sur la variante plugin.

📈

/tmc-arb

Top stratégies delta-neutres maintenant. Appelle find_arbitrage_strategies (count 5, liquidité $1M, 7j), rend une table Ticker | Long→Short | APR. Args = raffinement (nombre = count, liste = filtre exchanges).

⚖️

/tmc-rates

Compare les funding rates d'un ticker. Appelle get_ticker_markets (uppercased), trie par |APR| desc, remonte la paire suggestedArb. N'utilise jamais get_funding_rates.

🎛️

/tmc-setup

Setup interactif : exchanges par défaut, seuils de liquidité, tolérance au risque, count, fenêtre. Écrit ~/.toomanycooks/preferences.md — relu à chaque requête.

Installer

De zéro à requête

Le serveur MCP étant lancé via npx, rien à installer globalement.

Récupérer une clé API (une fois, pour tout)

Tier gratuit (100 req/jour) sur toomanycooks.app/dashboard/api-keys. La clé ressemble à tmc_live_… — référencée partout comme TMC_API_KEY.

Choisir sa plateforme & déposer la skill/rule

Copier le fichier généré dans le chemin de la plateforme (voir tableau ci-dessus). Détail complet par plateforme dans INSTALL.md.

Brancher le serveur MCP

Ajouter le bloc mcpServers (forme Claude Desktop / Claude Code ci-dessous). Codex stocke ça dans ~/.codex/config.toml.

Config MCP standard

{
  "mcpServers": {
    "toomanycooks": {
      "command": "npx",
      "args": ["-y", "@toomanycooks/mcp-server"],
      "env": { "TMC_API_KEY": "tmc_live_..." }
    }
  }
}

Claude Code plugin — une ligne

# marketplace auto-portée par le tree dist/
/plugin marketplace add naavix/toomanycooks-plugin
/plugin install toomanycooks@toomanycooks

# tester le build local avant publication
claude --plugin-dir ./dist/claude-code-plugin

À l'activation, Claude Code demande la TMC_API_KEY (déclarée sensitive en userConfig, stockée dans le keychain OS).

Maintenir le dépôt

Le workflow qui pique

Ne jamais éditer dist/ à la main. On corrige la source canonique ou la recette, puis on régénère.

npm install
npm run build      # régénère dist/ (toutes plateformes)
npm test           # vitest : snapshot/plateforme + unit
npm test -- -u     # ré-bénit après modif intentionnelle
npm run check      # Biome lint + format
npm run mirror -- --platform=<name> --repo=<git-url>

CI · build.yml

build + test sur chaque push/PR.

CI · mirror.yml

sur push main, pousse les trees dist/<platform> vers les repos marketplace standalone (auth MIRROR_PUSH_TOKEN).

Ajouter une plateforme

créer platforms/<name>/recipe.json (+ header.md optionnel) → auto-découvert. L'ajouter à PLATFORM_OUTPUTS dans les tests.
